## Decisions

| ID | Topic | Decision | Reason |
|---|---|---|---|
| UB-9 | Colour contrast | Text, links and filled buttons use InSite blue 2 (`#1A6FAA`, 5.4:1 on white); its hover is the new blue 3 (`#155A8A`). Brand blue (`#187FBF`) stays for borders, rings and accents. Error text uses the new `--color-danger` (`#A8401A`, 6.2:1); the brand orange marks borders only. The top nav is blue 2. Shared classes `btn-primary`, `btn-secondary`, `btn-ghost`, `field` and `link` live in `globals.css`. | Brand blue on white is 4.35:1 and the orange 3.3:1, below WCAG AA's 4.5:1, which the brand skill also requires (as UB-5 did for muted text). The end-to-end axe checks include contrast. |
| UB-10 | Stream client | `RunStream` (`src/lib/stream/run-stream.ts`) reads one turn's SSE (`SseParser`), delivers each event once by `seq`, and reconnects with `GET /v1/runs/{id}/events` and `Last-Event-ID` after a drop or `idleTimeoutMs` without an event or heartbeat, with exponential backoff up to `reconnectAttempts`. Before the first event it repeats the start under the same `Idempotency-Key` (the run's client key), which replays the same run. It retries only failures without a runtime answer (no response, 502, 504); a runtime refusal (`OVERLOADED`, `RATE_LIMITED`, `RUN_IN_PROGRESS`) is shown with Retry. Tunables are in `publicConfig.stream` (with `NEXT_PUBLIC_STREAM_*` overrides). | Case U-04. Retrying an explicit refusal automatically would answer load shedding with more load and hide the refusal from the user (case U-10). |
| UB-11 | Live and saved messages | The run store (`src/store/run.ts`, Zustand) keeps live runs by a client key, outside React, so a stream survives navigation (the home page starts a run and the chat page takes it over once `run.started` names the session). At the end of a turn the session's messages, the session and the session list are refetched; a live run's input and answer are hidden once its saved user and assistant messages have loaded. A stopped or failed run's live text stays in the tab. | One source of truth after a turn (the saved messages), no duplicate bubbles, and Stop keeps the partial text (case U-03). |
| UB-12 | Export to PDF | Export prints the conversation with a print stylesheet (navigation, sidebar, composer and actions hidden); the browser's "Save as PDF" writes the file. No PDF library. | Charts, grids, tables and any script or language print as shown; a generated PDF would need fonts for every script and would drop charts. |
| UB-13 | End-to-end targets | `fakes` (default): Playwright starts the runtime server with fakes (`npm run e2e:server` in the server repository: the real API, run driver, node kinds, streams and datasets over its in-memory gateway, a scripted model, the fake MCP server and cache, and a local token issuer) and this UI built and started against it. Sign-in is the Auth.js session cookie with the fake issuer's token, encrypted with an e2e-only secret, which is what a real sign-in stores. `dev`: `E2E_TARGET=dev` with `E2E_BASE_URL`, a real sign-in (`E2E_USERNAME`, `E2E_PASSWORD`) and the agents in `E2E_DEV_AGENTS`; tests that need the scripted workflows skip there. CI runs the `fakes` target when the `RUNTIME_SERVER_READ_TOKEN` secret is set (the server repository is private, UB-7), and skips the job otherwise. | Plan task U5-10 and checkpoint M5. Mocking the runtime in the UI repository would test the UI against a second, hand-written runtime. |
| UB-14 | Interrupt forms | `src/lib/schema-form.ts` turns the answer schema's properties into fields (text, long text, number, integer, boolean, choice, JSON) with the checks the UI can make (required, bounds, length, pattern, choice). An answer schema with `approved: boolean` gets Approve and Reject with an optional comment, whatever the node type. The runtime's own errors show beside their field: the server now returns `INTERRUPT_ANSWER_INVALID` with `details` paths (server decision 0008). | Case U-07 without a form library; the runtime validates every answer anyway. |
| UB-15 | Feedback | Helpful is rating 1 and Not helpful is -1 (`FeedbackRequest.rating`, -1 to 5); a comment is a second request with the same rating. | The contract's range; one click rates, the comment is optional. |
| UB-16 | Grid | AG Grid Community, infinite row model with pagination: each block of `pageSize` rows is one `GET /v1/datasets/{id}` page; the first sorted column becomes `sort` (`field` or `field:desc`) and text "contains" filters become `filter`. Builder column definitions are allow-listed (`field`, `headerName`, widths, `sortable`, `resizable`, `hide`); renderers and formatters are dropped. The grid and the chart load only when a message has one. | Case U-06; parts are data (design Section 12.5). |
| UB-17 | Chart | ECharts with the SVG renderer. The option is copied as plain data again; a chart that names a dataset and has no `dataset.source` gets the dataset's first page (`paging.chartRows`) as its source. | Defence in depth beside the runtime's allow list. |
| UB-18 | Accessibility checks | Component tests run axe with the WCAG 2.1 A and AA rules in jsdom, without colour contrast and frames (jsdom has no layout or frames); the end-to-end suite runs the same rules in Chromium, contrast included. A principle test scans every component for literal user-facing text (JSX text and `aria-label`, `title`, `placeholder`, `alt`, `label` attributes). | Case U-12 and design rule 6. |
| UB-19 | Run page | `/runs/{id}`: status, tokens and cost; steps from the run's events replayed from the start of its buffer, else from its saved node timeline (`/nodes`); node inputs and outputs when the runtime returns them; the trace tree for trace roles (a 403 or 404 shows that the trace is not available). | Case U-08; events are not stored (design Section 12.4). |
| UB-20 | Expired session | Any 401 from the proxy shows a sign-in prompt that returns to the page. Composer drafts are kept in session storage per conversation (`new:<workflow>` before the session exists), so the text survives the sign-in and a reload; a refused send keeps the text in the composer. | Case U-11 (the silent refresh is UB-8). |
| UB-21 | Empty success bodies | The API client returns `undefined` for a success response without a body. | Feedback answers `201` with no body; parsing it as JSON failed (found by the component tests). |
| UB-22 | The dev target | `E2E_DEV_AGENTS` names each dev agent by `{id, name}`: the ID the run request carries, and the catalog card's exact title (dev names can share a prefix). Against a real model the specs ask `E2E_DEV_QUESTION` (an answer without tools) and check what any answer must do (stream in growing prefixes, be saved, keep its text after a reload, get its actions); the scripted answer's exact text is checked against fakes only. Timeouts are longer on dev (`E2E_TIMEOUT_MS`, `E2E_EXPECT_TIMEOUT_MS`). | A real model's words cannot be asserted; the behaviour can. |
| UB-23 | Public OIDC clients | A client without a secret (the Cognito pool's app client) authenticates at the token endpoint with PKCE only (`token_endpoint_auth_method: none`, `src/lib/auth/provider.ts`). | Auth.js otherwise sends a Basic header with an undefined secret, which Cognito refuses; found by the dev run. |
